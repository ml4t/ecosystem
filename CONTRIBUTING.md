# Contributing

Use the GitHub repository that owns the affected code. Cross-library policies, qualification,
documentation process, and coordination belong here; implementation defects belong in the affected
library.

Before opening an issue, search existing ecosystem and library issues. Public bug reports must state
the affected package version, environment, expected behavior, observed behavior, and a minimal
reproduction. Report suspected vulnerabilities through the private process in `SECURITY.md`.

User-visible changes and defect fixes require an issue and a pull request that closes it. Run the
quality gates in `AGENTS.md` before requesting review.
