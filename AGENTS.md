# ML4T Ecosystem Agent Guide

This repository holds the standards, qualification checks, and cross-library evidence shared by the
stable ML4T libraries. It contains no library source code and is not a runtime dependency. Change a
library's code in that library's repository, following its own `AGENTS.md` and `CONTRIBUTING.md`.

`config/libraries.toml` is the authoritative inventory. Repositories outside it are not covered by
stable-library qualification. Each library's `docs/book-guide/index.md` maps book chapters to its
public API.

## Repository layout

- `CONTRIBUTING.md`: how to propose a change; `SECURITY.md`: private vulnerability reporting.
- `docs/standards/`: the normative requirements, including compatibility, release qualification,
  documentation, issues and pull requests, and agent guides.
- `decisions/`: numbered records of accepted policy changes and exceptions.
- `config/`: the library inventory, shared labels, and policy values the checks read.
- `src/ml4t_ecosystem/` and `tests/`: the `ml4t-ecosystem` command that implements the checks.
- `status/` and `reviews/`: dated qualification evidence and cross-library reviews.

## Sources of truth

When they disagree, prefer in this order: PyPI metadata for what is published; the library's
default branch for current source and workflows; the library's `AGENTS.md` for its commands and
constraints; `docs/standards/` here for shared requirements; `status/` and `reviews/` for evidence.
A local tag, feature branch, or copied status table is not release evidence.

## Changing shared policy

- Requirements in `docs/standards/` change through a pull request here, recorded in a new file
  under `decisions/` when the change alters a release criterion or grants an exception.
- Never weaken a shared check inside a library to make its CI pass. If the requirement is wrong,
  change it here.
- Shared compatibility: Python 3.12 through 3.14 on Linux, macOS, and Windows, with Python 3.15
  prereleases tracked as described in `docs/standards/compatibility.md`.

## Quality gates

```bash
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest -q
uv run mkdocs build --strict
pre-commit run --all-files
```

Install hooks once with `pre-commit install`, and never bypass them.

## Safety

- Never commit `.env` files, credentials, private security reports, `.claude/`, `.codex/`,
  `.workspace/`, or another repository. The root `.gitignore` ignores everything not explicitly
  allowed; never force-add an ignored path.
- Keep internal planning, agent state, and operational detail out of tracked files.
- `status/current.json` and `status/current.md` are generated by `uv run ml4t-ecosystem collect`;
  never edit them or any generated changelog by hand.
